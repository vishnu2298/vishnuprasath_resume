Selected work

Systems I've built and led

Client and product names stay confidential, and nothing here claims numbers I can't support.

01

Commerce platform backend

Backend services for a commerce platform that combines product discovery, comparison, affiliate commerce, rewards, analytics and AI-assisted product information.

The decision that shaped it

Search, comparison, rewards and analytics were separated into focused services, so each could change and be released without touching the others.

Node.js · MongoDB · Elasticsearch · Kibana · React Native · Angular · AI / LLM · REST APIs · Docker · Azure

02

Recommendation engine

Personalized product recommendations built from user behaviour, product relationships and trending signals.

The decision that shaped it

Candidates come from inexpensive behaviour and product signals first; AI reranking only runs on the short list, and refreshes are scheduled instead of computed on every request.

Node.js · Python · MongoDB · Elasticsearch · LLMs · SerpAPI

03

Product search with model-level intent

Fresher, more relevant product search that combines local inventory with external search results.

The decision that shaped it

Detect the product and model in the query before matching, so a search for one specific model returns that model instead of everything that shares its name.

Node.js · Elasticsearch · MongoDB · Search APIs · Product APIs

04

Product comparison with background enrichment

Comparison of merchant offers, prices and affiliate links, with AI-generated product insights added in the background.

The decision that shaped it

AI enrichment runs lazily in background workers and is cached, so a comparison response never waits on a model call.

Node.js · MongoDB · Elasticsearch · AI / LLM · Search APIs

Earlier enterprise work

  1. The problemWhat I did about it

  2. Search

    Local product data becomes stale.

    Combine local inventory with fresh external search and configurable refresh logic.

  3. Architecture

    A large monolithic backend becomes difficult to maintain.

    Separate responsibilities into focused services, migrating one boundary at a time instead of rewriting.

  4. AI

    AI processing increases API latency.

    Move enrichment into background workers, process lazily and cache the result, so responses don't wait on a model.

  5. Integrations

    Different external systems provide inconsistent data.

    Build normalization and service-level integration layers.

  6. Recommendations

    Recommendations need more than static rules.

    Combine behavioral signals, product relationships, trending data and AI reranking.

How I approach engineering

  1. 01

    Build for the real problem

    Don't build technology just because it is available.

  2. 02

    Keep systems maintainable

    Good architecture should help the next developer understand the system.

  3. 03

    Automate what repeats

    If a process happens repeatedly, look for a way to automate it.

  4. 04

    AI should be practical

    Use AI where it creates measurable product or engineering value.

  5. 05

    Design for change

    Systems evolve. Architecture should allow change without rewriting everything.

  6. 06

    Observe before rewriting

    Understand existing systems before replacing them.
